 Technology stack

 Frontend: Vite + React and Recharts. Backend: Python 3.11+ and FastAPI. Database: a local SQLite file
 accessed through Python sqlite3 and the Repository interface. Use pytest, ruff and mypy for Python
 checks and GitHub Actions for CI on main.
 The frontend has four screens: Dashboard, Transactions, Budgets and Accounts. Task #05 builds the first
 Dashboard and configures SQLite. Keep course-required CLI behavior unless the professor approves
 substitution.

 Access model

 The course demo runs locally for one user with synthetic data, so it opens directly to the Dashboard.
 React sends changes to FastAPI, which saves them to the SQLite file. The file retains records across
 refreshes and restarts. Login can be added for hosted access. Add signup later if users need to register
 themselves.

 What changed from v5.1

 Named owners, a React outcome for every task, AI-agent prompts, updated kickoff and main-only Git
 workflow. Original dates and estimates are planning baselines unless revised here. Re-estimate the
 added frontend effort at the kickoff.

Workflow and Definition of Done

 GitHub uses only main

 Use main as the sole GitHub branch. Coordinate one writer per shared area. Pull or fetch the latest main
 before work and again before pushing. Review a diff with the assigned reviewer before pushing small
 commits. Use clear commit messages. Run local checks before pushing and check CI on main. Never
 force-push.
 Erti reviews Isa. Isa reviews Florent. Florent reviews Erti. Record reviewer approval in the task card or
 meeting notes. Tag the verified main commit v1.0-freeze at the freeze.

 React delivery checks

 The relevant screen or evidence satisfies the task’s React deliverable. For UI changes, verify keyboard
 access, labels, visible focus, narrow-width layout and applicable loading, empty, failure and success
 states. Use server-calculated totals, stable IDs and decimal amount strings. Test with synthetic data.

 Engineering and AI use

 Meet the task-specific acceptance checks and confirm the prerequisites on main. Keep public Python
 code typed and documented. Run pytest, ruff and mypy plus React lint/build and the relevant browser
 checks. A teammate reviews changes and can explain the implementation.
 Paste one prompt at a time into the AI agent and give it the corresponding task details. Review the diff
 and test results yourself. Record relevant AI assistance and sources, and use synthetic data and
 placeholders.

 Working agreements

 Use the Trello card number when coordinating. Raise blockers in the group chat the same day. Defer
 Could features first, then agreed Should features. Confirm any change to a Must requirement with the
 professor.

 3. Configure a SQLite file using Python sqlite3. Use data/tracker.sqlite3 by default, allow a path override,
 keep the file out of Git and add a repeatable initialization command with optional synthetic seed data.
 4. Build the Dashboard described below. Use fixture data until #19 wires the live summary. Verify a
 synthetic SQLite record survives backend restart. Complete domain persistence in #18.
 5. Document setup, the database path and demo reset in the README. Run Python checks and React
 lint/build in CI on main. Review changes before pushing.

 Done when

 • Python installs and React builds on a fresh clone.
